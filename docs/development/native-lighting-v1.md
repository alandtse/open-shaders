# Native Lighting v1

Native Lighting consumes the current `DX12NativeScene::SceneFrame` after opaque raster capture. Native Scene owns the prepared TLAS, geometry, materials, camera, raster depth and prepared light data; lighting owns its descriptor heap, dispatch, outputs and completion fence. It does not write to the raster scene or the shadow mask.

The pass traces one primary receiver ray per eligible non-culled pixel. Comparison mode also traces culled pixels for its reference output. Supported opaque and alpha-tested candidates share the scene's material rules. After checking the hit against raw raster depth, it evaluates the material once and traces at most one deterministic visibility ray per eligible point light. The same visibility and attenuation feed the diffuse and specular BRDFs. The raster hit-distance tolerance is `max(2 world units, distance * 1e-5)`; this is a conservative initial threshold and still needs runtime validation.

The current Native Scene mask uses stochastic emitter sampling and does not publish enough evidence to prove camera and per-light equivalence to deterministic lighting. Consequently its authority flag is always false for v1: enabling mask culling records mask-unavailable pixels and runs the normal path. Zero weighted visibility from the current mask is not treated as proof that the deterministic rays are blocked. The shader includes the conservative per-pixel rejection gate for a future authoritative mask; it requires a matching raster receiver, a valid traced sample, finite positive hit distance and instance, and exactly zero visibility.

`GetContribution(frame)` offers DX12-owned resources in `Contribution::Output` order. Diffuse and specular contain linear raw direct radiance. Validity is R32_UINT: 0 unavailable, 1 traced, 2 validly culled, 3 unsupported. ReceiverGuide contains the evaluated normal and prepared instance index plus one. The optional debug texture uses green for traced, cyan for culled, magenta for unsupported and black for unavailable. The contribution carries frame, scene revision, dimensions, active lobes, intensities, and producer fence/value. Consumers wait on that fence, transition resources from COMMON and return them to COMMON, call `RetainContribution` with their completion fence, and retain the borrowed frame through submission. Calls are made on the render thread.

Enable **Compare culling on and off** and **Early shadow-mask culling** to publish additional no-cull diffuse/specular comparison textures. Non-culled outputs and comparisons share the same evaluated values and one traversal; when a future authoritative mask culls a pixel, comparison mode still traces that pixel once to generate its no-cull reference. Because the current mask is non-authoritative, this mode currently exercises the fallback rather than demonstrating a culling gain. No image comparison or visual consumption is claimed by submission counters.

Counters are read back only after the producer fence completes. They distinguish candidate pixels, mask rejections and unavailable masks, primary queries/hits/misses, evaluated materials, secondary queries, evaluated lights, valid lobe outputs, unsupported pixels, and readback failures. Native Composite can add current-frame valid diffuse and specular to the raster baseline. The output stays DX12-owned; counter readback is to CPU memory, not a DX11 frame transfer.

This first implementation is flat-screen only and covers the prepared static scene and up to 32 prepared point-light baselines. It does not establish dynamic-world, moving-light, animated-material, full receiver coverage, image quality, visual consumption, or performance. Flat and VR runtime validation remains the repository owner's responsibility; the existing rendering path is retained when this feature is unavailable.
